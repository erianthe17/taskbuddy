## Code notes (limits and where they live)
- Title: mobile min 5 / max 120 on the trimmed text (`HOCreateJobScreen.tsx:442-444`), typing capped by `maxLength={120}` (`:1001`); DTO `@Length(5,120)` (`jobs.dto.ts:57`); DB check 5-120 (`0001*.sql:81`). Match. Submit sends `title.trim()` (`:542`).
- Description: min 20 / max 750 on the trimmed text (`:446-448`), `maxLength={750}` (`:1038`), counter shows the raw length (`:1040`); DTO `@Length(20,750)` (`jobs.dto.ts:61`); DB check 20-750. Match. Submit sends `.trim()` (`:543`).
- Tasks: required on mobile (`:439-441`) though the DTO makes them optional (`jobs.dto.ts:106-111`: `ArrayMaxSize(20)`, each `Length(1,120)`); cap `MAX_TASKS = 20` (`:163`, enforced silently at `:413` and `:421`); custom input `maxLength={120}` (`:966`), trimmed (`:420`), duplicates ignored by exact string (`:421`).
- Auto-draft (`:394-406`): title `${category}: ${firstTask}` (can reach 130 chars), description `${category} service needed. Tasks: ${tasks.join(', ')}.` with no length cap, so 20 long tasks exceed 750 and trip the step-3 check with no typing by the user. Stops per field once that field is touched.
- Budget: mobile `isValidBudget` (`:277-286`): trims, strips ALL commas, `Number()` finite, `> 0`, at most 2 decimal places; no maximum. Blur reformats valid values with `toFixed(2)` (`:288-291`, `:1168`). Required on mobile (`:465`) but DTO `@IsOptional @IsNumber({maxDecimalPlaces:2}) @IsPositive` (`jobs.dto.ts:81-85`); DB `numeric(12,2)` with `check (budget > 0)` (`0007_job_pricing_schedule_photos.sql:23-24`), so about 9,999,999,999.99 is the true ceiling and nobody enforces anything lower. Mismatches to flag: required vs optional (known product call), no maximum anywhere, `Number()` accepts "1e3" and "0x10", comma stripping is positionless.
- Date/time: required on mobile (`:452-453`), optional in the DTO (`jobs.dto.ts:89-92`). Calendar `minDate` is today (`:1302`), no `maxDate`. Past instant rejected on Next (`:456-464`), not on Post (`:529-560`). DTO allows 5 minutes of past grace (`jobs.dto.ts:34`, `:42`), so mobile is stricter on Next but can still be stale by Post.
- Address: required, trimmed (`:436`), geocoded on Next if unverified (`:364-386`). Geocode DTO `Length(5,300)` (`jobs.dto.ts:123-124`); suggestion minimum 3 chars (`AddressField.tsx:109`). `address` in the DTO is only `@IsNotEmpty` with no length cap.
- Photos: max 6 (`:482`, `:500`; DTO `ArrayMaxSize(6)`, `jobs.dto.ts:97`); upload content type chosen by file extension only, default `image/jpeg` (`api.ts:673-678`); backend accepts only jpeg/png/webp (`uploads.constants.ts:26-30`); no `file_size_limit` is set for `job-photos` in migrations (set only for provider-portfolio, `0044_provider_portfolio.sql:2-4`). Upload happens before the job is created (`:533-537`), `Promise.all` fails as a whole.
- Submit guard: `submitJob` (`:529-560`) has no re-entry guard beyond `disabled={submitting}` (`:1252`); `handleNext` (`:572-581`) has none either.
- Exit: header arrow uses `handleExit` (`:622-628`) and shows "Discard job draft?" when `hasProgress` (`:583-586`, includes the prefilled `location`). Hardware Back goes through `App.tsx` `BackHandler` (`:265`, homeowner branch `~:283-290`) and calls `hoBack()`, bypassing `handleExit` (E2E-051). Footer Back is `handleStepBack` (`:588-591`). The `ConfirmationModal` was not seen to set `onRequestClose` (grep found it only in `SheetFrame.tsx:117`).
- Wallet: the wizard never reads the wallet; posting does not hold funds (hold is at hire, BACKEND_SCHEMA "escrow" around lines 850-866). So no "insufficient balance" message exists on this screen.
- Related findings: E2E-050 (Post Another Job leaves address empty), E2E-051 (hardware Back exits without the prompt).
