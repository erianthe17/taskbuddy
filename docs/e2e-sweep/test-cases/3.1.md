## Pre-read notes (mobile vs DTO, code read, not yet verified on device)
1. Budget: the DTO makes it optional (`backend/src/jobs/dto/jobs.dto.ts:80-85`, `@IsOptional`, `@IsPositive`, 2 dp) and `api.ts:1149` types it `budget?`, but the wizard requires it (`HOCreateJobScreen.tsx:465` "Please set a budget for this job.", asterisk at `:1152`) and always sends it (`:548`). So "budget optional" cannot be tested through the UI; 3.1-42 and 3.1-43 cover both sides. Product call: keep required in the UI, or allow skipping.
2. `scheduled_at` is optional in the DTO (`jobs.dto.ts:89-92`, 5-minute past grace at `:34`) but the wizard requires date and time (`:452-453`) and rejects any past instant, including the DTO's 5-minute grace (`:456`). Stricter on mobile, so no breakage, but an intentional difference.
3. Matching limits (no mismatch): title 5-120 (`:443-444` vs `jobs.dto.ts:57`), description 20-750 (`:446-448` vs `:61`), photos max 6 (`:482`, `:500` vs `:97`), tasks max 20 of 1-120 chars (`:163`, `:423` vs `:108-110`), budget 2 dp (`:283-284` vs `:82`).
4. The auto-draft can break the limits: the drafted description joins all task labels (`:402`, no length cap; `maxLength` only blocks typing) so 20 long tasks give over 750 chars and a step-3 error the user did not cause; the drafted title is `${category}: ${first task}` (`:397`), which can pass 120 for a 120-char first task. Edge for 3.2.
5. No `accessibilityLabel` on the header back arrow (`:714`) or the add-task + button (`:968`).
6. Only the time uses `@react-native-community/datetimepicker` (`:1327-1333`, `mode="time"`, `display="spinner"`); the date uses `react-native-calendars` in a sheet (`:1284-1315`). So "Android datetimepicker" for dates is not applicable; the date is a JS calendar.
7. Stale location confirmation: "Enter custom" clears only the text (`:768-772`) and leaves `resolvedCoordinates` and `geocodedAddress` in place, and `AddressField.tsx:145` calls `onResolve(null)` only if `resolvedTextRef` is set, which a profile prefill (`HOCreateJobScreen.tsx:333-341`) never sets. The "Location confirmed" card and map can therefore describe the old address while the field shows new text, until Next re-geocodes (`:367`). See 3.1-23.
8. Success copy (`:675`) says providers in the area "will be notified"; the product flow notifies only top-8 ML invites after the deadline (CLAUDE.md flow). Check 3.1-16.
9. `useProfileLocation` (`:225`) is only set from the step-1 prompt and not synced to later location edits, so the "Use default" highlight can be wrong after step 2 changes. Cosmetic.
